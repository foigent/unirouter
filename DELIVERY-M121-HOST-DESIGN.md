## Verified gap

The candidate binary and immutable migration artifact support M113–M121. `scripts/compatible-expand.py` accepts only M113–M118. `scripts/internal-target-rollout.py` permits a changed migration bind mount only when exactly one named pair was added, so the daily M115 artifact cannot roll directly to the one M121-capable candidate source. The candidate Compose chain also adds eight source flags/storage settings absent from M115; its exact effective-config comparison currently rejects those additions.

Each pair binds exact named version plus SHA-256 of both up and down bytes. The old source's complete committed migration ledger must equal the DB ledger and end at `from_head`; `git diff` must show *only* addition of those exact suffix pairs, with no changed/deleted old migration bytes. Keep existing source/image/Compose/backup/ingress identity checks. No arbitrary target, unknown fields, rewritten old migration, migration execution, or second deployment controller.
3. 5. Update the CI-only carrier read fixture from exact M117/M118 to exact M120/M121; extend Python tests for M115→M121 and intermediate exact suffixes, missing/extra/reordered pairs, modified old migration, digest mismatch, disabled flags and check no-write boundaries. Retain binary M115–M121 migration/recovery tests. Run release metadata, targeted Go/Python tests and required project gates. Document the precise sequence in the existing runbook.

## Intended sequence and limits

One committed M121-capable source and image can start on the **existing** M115 ledger only if its compatibility/recovery checks pass against the actual Target fleet. The named carrier rolls that same source once without applying SQL. Then run `compatible-expand check` and `apply` in order M116, M117, M118, M119, M120, M121, with each exact up digest, ledger/health/manifest/fleet re-read and backup/recovery gate as defined by the binary. Do not skip any head or call bare migrate/SQL. This avoids six temporary source releases. The returned DB head is not a license/publication/traffic grant. An old M115 binary cannot be assumed rollback-safe once the DB advances; recovery must use a tested compatible artifact or restored backup with the applicable rebase rules.

Production/deployment approval, host capacity and the actual continuity chain are owned by the coordinator; this proposal qualifies only source code and local tests.
