# Test Plan（验收测试计划）

> **版本**：v1.1
> **日期**：2026-06-27
> **用途**：Phase 1 验收测试用例

## 一、测试环境

| 组件 | 配置 |
|------|------|
| Docker Compose | 4 容器（backend + frontend + postgres + redis） |
| 测试数据 | 1 个 platform_admin + 1 个 org + 1 个 user + 1 个 wallet |
| 上游渠道 | 至少 2 个（DeepSeek + 1 个海外模型） |

## 二、核心链路测试

### TC-01: API Key 认证

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 创建 API Key | 返回完整 Key（ur-XXXX-...） |
| 2 | 用 Key 调用 `/v1/models` | 200 + 模型列表 |
| 3 | 禁用 Key | 返回成功 |
| 4 | 用禁用的 Key 调用 | 401 + `auth_error.invalid_api_key` |
| 5 | 用不存在的 Key 调用 | 401 + `auth_error.invalid_api_key` |

### TC-02: IP 白名单

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 设置 Key 的 IP 白名单为 "127.0.0.1" | 返回成功 |
| 2 | 从 127.0.0.1 调用 | 200 |
| 3 | 从其他 IP 调用 | 403 + `auth_error.ip_denied` |
| 4 | 清空 IP 白名单 | 返回成功 |
| 5 | 从任意 IP 调用 | 200 |

### TC-03: 模型权限

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 设置 Key 的 allowed_models 为 "deepseek-v4-pro" | 返回成功 |
| 2 | 调用 deepseek-v4-pro | 200 |
| 3 | 调用 gpt-5 | 403 + `auth_error.model_not_allowed` |

### TC-04: 非流式聊天补全

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | POST `/v1/chat/completions`（非流式） | 200 + 完整 usage + `_uniroute.cost` |
| 2 | 检查 `_uniroute.request_id` | UUID 格式 |
| 3 | 检查 `_uniroute.cost.amount` | > 0 |
| 4 | 检查 `call_logs` | 记录存在，`usage_source = "upstream"` |

### TC-05: 流式聊天补全

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | POST `/v1/chat/completions`（stream=true） | SSE 流，Content-Type: text/event-stream |
| 2 | 验证每个 chunk 格式 | `data: {json}\n\n` |
| 3 | 验证心跳 | 每 15s 有 `: ping\n\n` |
| 4 | 验证结束标记 | `data: [DONE]\n\n` |
| 5 | 验证最后一个 chunk | 包含 `_uniroute` 字段 |
| 6 | 检查 `call_logs` | 记录存在 |

### TC-06: 预冻结计费

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 充值 ¥10 | 余额 = 1000 分 |
| 2 | 调用 API（消耗约 ¥0.05） | 200，余额 = 995 分 |
| 3 | 检查 `wallets.frozen` | 0（已结算） |
| 4 | 检查 `transactions` | 有 freeze + settle 记录 |

### TC-07: 余额不足

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 将余额调至 0 | 余额 = 0 |
| 2 | 调用 API | 402 + `billing_error.insufficient_balance` |
| 3 | 检查 `call_logs` | 无记录（未转发） |

### TC-08: 流式中断结算

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 充值 ¥10 | 余额 = 1000 分 |
| 2 | 发起流式请求 | SSE 流开始 |
| 3 | 收到前 5 个 chunk 后断开连接 | 流终止 |
| 4 | 检查 `call_logs` | `usage_source = "estimated"`，费用 > 0 |
| 5 | 检查钱包余额 | 已扣除估算费用 |

### TC-09: 幂等性

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 发送请求（X-Request-Id: uuid-1） | 200 |
| 2 | 用相同 X-Request-Id 重发 | 200 + 相同结果（不重复扣费） |
| 3 | 检查 `freeze_idempotency` | status = "Success" |
| 4 | 检查钱包余额 | 只扣了一次 |

## 四、稳定性测试

### TC-14: 渠道熔断

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 配置 2 个渠道（同模型） | 2 个 active 渠道 |

### TC-15: 敏感词拦截

### TC-16: 限流
