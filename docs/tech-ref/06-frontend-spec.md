# Frontend Spec（前端页面规格）

> **状态**：PRD1 时期的历史设计快照，不是当前页面、路由或 API 验收合同。
> 当前实现以 `frontend/src/navigation.tsx`、`frontend/src/App.tsx`、
> `frontend/src/api/client.ts` 和 `docs/tech-ref/05-openapi-spec.yaml` 为准；
> 不得仅依据本文新增、删除或重命名当前功能。
> **版本**：v1.0
> **日期**：2026-06-18
> **用途**：解释最初设计意图和历史差异

---

## 一、技术方案

**保留 OneAPI 原生前端**（React 18 + Semi Design + Vite），新增页面统一使用 Semi Design 保持风格一致。

**理由**：3.5 人团队维护两套 CSS 框架（Semi + Tailwind）成本过高。路由级分离增加复杂度。统一 Semi Design 可以复用 OneAPI 原生组件。

**构建与交付**：Vite 输出到被 Git 忽略的 `frontend/dist/`；
`frontend/Dockerfile` 在独立构建阶段生成该目录，并将其复制到 Nginx
`/usr/share/nginx/html`。后端 Go 镜像不内嵌前端静态资源。仓库不提交编译产物，
发布时必须从待发布 commit 重新构建前端镜像。

## 二、路由结构

```
/admin                          → Dashboard
/admin/channels                 → 渠道管理
/admin/channels/:id/test        → 渠道测试
/admin/keys                     → API Key 管理
/admin/billing                  → 账单
/admin/billing/reconciliation   → Token 对账
/admin/logs                     → 调用日志
/admin/settings                 → 系统设置
```

**布局**：

```
┌─────────────────────────────────────────────────────┐
│ [今日] [本周] [本月]                                  │
├──────────┬──────────┬──────────┬──────────┤
│ 总调用量  │ 总费用    │ 活跃 Key │ 活跃组织  │
│ 12,345   │ ¥1,234   │ 45       │ 8        │
├──────────┴──────────┴──────────┴──────────┤
│                                             │
│  [费用趋势折线图]                              │
│                                             │
├──────────────────────┬──────────────────────┤
│  Top 5 模型（调用量）  │  Top 5 模型（费用）    │
│  1. deepseek-v4-pro  │  1. gpt-5            │
```

**交互**：
- 切换时间周期自动刷新数据
- 数字卡片支持千分位格式化
- 费用趋势图使用 Semi Design 的 Chart 组件

### 3.2 渠道管理 (`/admin/channels`)

**数据源**：
- 列表：`GET /api/v1/admin/channels`
- 创建：`POST /api/v1/admin/channels`
- 更新：`PUT /api/v1/admin/channels/:id`
- 测试：`POST /api/v1/admin/channels/:id/test`

**布局**：

```
┌─────────────────────────────────────────────────────┐
│ [+ 创建渠道]                                         │
├─────┬────────┬────────┬────────┬──────┬──────┬──────┤
│ ID  │ 名称    │ 厂商    │ 模型    │ 优先级│ 状态  │ 操作 │
├─────┼────────┼────────┼────────┼──────┼──────┼──────┤
│ 1   │ DeepSeek│ deepseek│ v4-pro │ 1    │ 🟢   │ 编辑 │
│     │ Official│        │ v4-flash│      │      │ 测试 │
│     │        │        │        │      │      │ 禁用 │
├─────┼────────┼────────┼────────┼──────┼──────┼──────┤
│ 2   │ OpenAI  │ openai │ gpt-5  │ 2    │ 🟡   │ 编辑 │
│     │ via 代理│        │ gpt-4o │      │ 迁移 │ 测试 │
└─────┴────────┴────────┴────────┴──────┴──────┴──────┘
```

**创建/编辑表单**：
- 名称（text）
- 厂商（select：deepseek / openai / anthropic / zhipu / ali / geminiv2）
- Base URL（text）
- 模型列表（text，逗号分隔）
- Model Mapping（JSON editor 或 key-value 表格）
- 上下文窗口（number）
- 默认最大输出（number）
- 优先级（number，越小越优先）
- RPM 限制（number）
- TPM 限制（number）
- API Keys（可动态添加多个）

**渠道测试弹窗**：
- 选择测试模型
- 输入测试消息（默认 "Hello, this is a test."）
- 点击"测试"→ 显示：响应内容 + 费用 + TTFT + 总耗时 + curl 示例
- 失败时显示：错误码 + hint + upstream_error

**状态标签**：
- `active` → 绿色
- `deprecated` → 黄色 + "推荐迁移"提示
- `disabled` → 灰色

### 3.3 API Key 管理 (`/admin/keys`)

**数据源**：
- 列表：`GET /api/v1/admin/keys`
- 创建：`POST /api/v1/admin/keys`
- 更新：`PUT /api/v1/admin/keys/:id`

**布局**：

```
┌─────────────────────────────────────────────────────┐
│ [+ 创建 API Key]                                     │
├─────┬────────┬────────┬──────┬──────┬──────┬────────┤
│ ID  │ 名称    │ 前缀    │ 组织  │ RPM  │ 状态  │ 操作   │
├─────┼────────┼────────┼──────┼──────┼──────┼────────┤
│ 1   │ 生产Key │ ur-0001│ Acme │ 60   │ 🟢   │ 编辑   │
│     │        │ -a3b8  │ Corp │      │      │ 禁用   │
└─────┴────────┴────────┴──────┴──────┴──────┴────────┘
```

**创建表单**：
- 组织（select）
- 名称（text）
- IP 白名单（text，逗号分隔，空表示不限制）
- 授权模型（multi-select，空表示不限制）
- RPM 限制（number，默认 60）
- RPS 限制（number，默认 10；后端兼容字段仍为 `qps_limit`）
- 预算上限（number，分，空表示不限制）

**创建成功弹窗**：
- 显示完整 Key（一次性，不可再次查看）
- 提供"复制"按钮
- 警告："请立即保存此 Key，关闭后将无法再次查看。"

### 3.6 调用日志 (`/admin/logs`)

**数据源**：`GET /api/v1/admin/logs?page=1&page_size=20&org_id=&model=&status=&start_time=&end_time=`

**布局**：

```
┌─────────────────────────────────────────────────────┐
│ 筛选：[组织▼] [模型▼] [状态▼] [时间范围] [查询]        │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┤
│ 时间  │ 组织  │ 模型  │ Token│ 费用  │ 延迟  │ 状态  │
├──────┼──────┼──────┼──────┼──────┼──────┼──────┤
│ 14:32│ Acme │ deep │ 1234 │ ¥0.3 │ 412ms│ ✅   │
│      │ Corp │ seek │      │      │      │      │
├──────┼──────┼──────┼──────┼──────┼──────┼──────┤
│ 14:31│ Beta │ gpt- │ 5678 │ ¥2.1 │ 1.2s │ ❌   │
│      │ Inc  │ 5    │      │      │      │ 502  │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┘
                    [分页：< 1 2 3 ... >]
```

**详情弹窗**（点击行展开）：
- request_id
- 完整 usage（prompt_tokens / completion_tokens / total_tokens）
- usage_source（upstream / estimated）
- cost_micros（十进制字符串；前端按 `1 CNY = 1,000,000 micros` 格式化）
- latency_ms / ttft_ms
- upstream_error（如有）
- is_stream

## 五、权限控制

前端根据 JWT 中的 `role` 字段控制菜单和按钮可见性：

| 角色 | 可见菜单 | 可见操作 |
|------|---------|---------|
| `platform_admin` | 全部 | 全部 |
| `org_admin` | Dashboard / Key / 账单 / 日志 | 本组织资源的 CRUD |
| `org_viewer` | Dashboard / 日志 | 只读 |
