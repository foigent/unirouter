# UniRouter Model Adaptation Learnings

This is the sole maintained long-term learning file for model adaptation.
Current code, Baseline/ADR, Target state and provider documentation remain the
authorities; Git retains event history. Entries stay only while their invariant
and executable enforcement remain applicable.

### MAR-001 Validate capability composition under effective defaults

- Invariant: A Profile may expose only request combinations that its exact provider surface can execute; individually valid capabilities do not prove their composition under omitted fields or provider defaults.
- Scope/Trigger: Any model Profile that combines reasoning defaults or toggles with tools, tool choice, structured output, streaming, media, cache or search.
- Enforcement: Typed normalization rejects impossible combinations before Freeze or credential use, and full prepare/admission/provider-payload regressions cover both omitted defaults and explicit overrides.

### MAR-002 Downgrade must not orphan newly introduced durable identities

- Invariant: A schema downgrade must refuse before mutation whenever the target predecessor cannot interpret a durable Profile attachment or immutable evidence introduced by the newer schema.
- Scope/Trigger: Append-only Profile, protocol, probe-contract or evidence identities added together with a migration compatibility ceiling.
- Enforcement: The down migration holds the shared lifecycle/table locks and rejects only durable identities the predecessor cannot interpret: Profile migrations guard retained attachments/probes/approvals, while probe-contract-only migrations guard retained evidence or projection-identity drift but permit unchanged pre-existing Profile attachments. A pre-mutation drift check and a pre-deletion no-residual postcondition preserve rollback atomicity in isolated PostgreSQL regressions.

### MAR-003 Share provider wire normalization between probe and runtime

- Invariant: A safe provider wire variation with unchanged canonical semantics is normalized at the lowest shared exact-scoped boundary available; probes add semantic assertions and never become proof of software-artifact correctness. Until one canonical delivery validator is shared, cross-delivery fixtures and public execution evidence are mandatory and a third provider-specific full envelope parser is a stop condition.
- Scope/Trigger: Typed provider probes and runtime delivery encounter the same provider-specific response variation, especially function tools, structured output, streaming and media.
- Enforcement: Exact-scoped normalizers validate duplicate JSON members before any map decoding, remove only safe provider wire variations and retain unknown siblings for the canonical guardrail. DeepSeek V4 and the exact Kimi K2.6/K2.7 Code non-stream function-tool contracts accept only a lexical non-negative child tool-call index and remove it before canonical delivery validation; Kimi K2.6 streaming removes only an empty-string delta reasoning member, while K2.7 SSE v4 retains and requires bounded reasoning evidence. Ordinary and Unicode escaped-equivalent duplicate-key regressions prevent last-wins normalization. Kimi non-stream Probe and runtime still have separate envelope parsers, so the same fixtures must pass both, unknown numeric usage extensions remain non-authoritative, and public UI/SDK delivery is required before live closeout. Immutable Probe Contract versions prevent failed historical evidence from being reinterpreted.

### MAR-004 Treat a terminal SSE error as an error after HTTP success

- Invariant: An HTTP 200 that later carries a terminal SSE error must not be projected as an empty successful stream; request identity and safe billing finality remain visible without exposing private content.
- Scope/Trigger: Streaming clients and UI workbenches that consume gateway SSE and may receive an error after response headers or partial output.
- Enforcement: The stream consumer records the terminal error event separately from content and renders its bounded code/message, request ID and billing status; a real `ReadableStream` regression forbids the `(empty stream)` success projection.
- Authority: `frontend/src/pages/DeveloperConsolePage.tsx`; `frontend/src/pages/__tests__/DeveloperConsolePage.test.tsx` test `surfaces a terminal SSE error instead of reporting an empty stream`.
- Status: active

### MAR-005 Keep operation protocol identity independent from capability evidence

- Invariant: Capability, catalog and live-evidence state cannot create a deployment operation protocol identity; a typed override must come from one explicit immutable identity declaration, while an invalid or ambiguous declaration fails closed instead of falling back to a generic protocol. Admin capability eligibility must likewise be projected by the service rather than recreated as a frontend Profile/protocol allowlist.
- Scope/Trigger: Canonical onboarding or attachment of a reviewed Profile to Chat, Responses, Messages or another typed operation surface.
- Enforcement: The server first resolves and validates the canonical base operation, then applies only a model-profile-owned exact override. `found=false` returns no fallback identity and preserves the caller-owned Chat, Responses or Embeddings base; resolver errors terminate onboarding. Unverified or legacy Profiles cannot carry typed declarations, and Chat contract registration alone grants no binding authority. The canonical operation projection returns exact `capability_probe_contracts`; the UI renders that projection and has positive Pro/Flash plus unbound-generic regressions instead of owning provider tuples.

### MAR-006 Keep customer sponsorship separate from platform operation

- Invariant: A platform operator may administer a workload-access flow but cannot substitute its own identity for the customer project member who supplies business sponsorship; credential scope can only narrow an approved Grant.
- Scope/Trigger: Platform-admin model validation that creates a workload Application, access request or application credential in another customer organization.
- Enforcement: The UI freezes the exact Application scope, loads only active members from its project, requires an explicit Sponsor, ignores late cross-scope responses and sends a server-normalized model allowlist. Offboarding preserves the backend's structured active-sponsorship diagnosis and directs the operator to revoke the old authorization after any independently sponsored replacement; it never implies that a new Grant detaches the old Sponsor. The backend remains authoritative for Sponsor membership, Grant containment, credential scope and atomic offboarding.
- Authority: `frontend/src/pages/ApplicationsV2Page.tsx`; `frontend/src/pages/UsersPage.tsx`; `frontend/src/pages/__tests__/WorkloadApplicationsPage.test.tsx`; `frontend/src/pages/__tests__/UsersPage.test.tsx`; `frontend/src/utils/modelList.ts`; `frontend/src/utils/__tests__/modelList.test.ts`; `internal/accessprovisioning/service.go`; `internal/accessgrantboundary/resolver.go`; `internal/admin/workload_application_handlers.go`; `internal/admin/sponsor_transition.go`.

### MAR-007 Validate control-plane probes against public execution contracts

- Invariant: A server-owned capability Probe may narrow a request but may not bypass or contradict the exact public Execution Profile, admission grammar or its documented management API identity; a successful supplier response cannot repair an invalid Probe request.
- Scope/Trigger: Adding or changing a typed provider capability Probe, its exact Profile/protocol binding, fixed request body or management API projection.
- Enforcement: Admin payload tests pin the server-owned request and its immutable summary to the same exact request body, Gateway regressions run that request shape through exact Profile validation and admission while rejecting obsolete aliases, and OpenAPI tests compare qualification identity enums with compiled bindings and cover provider validator error codes.

### MAR-008 Freeze the exact Target deployment command before schema change

- Invariant: A schema-ceiling deployment uses one explicit Compose project and ordered file chain, stops all old backend writers, runs one candidate CLI migration owner, then recreates matching stable/canary and frontend/Nginx provenance; `SKIP_MIGRATION` never bypasses the exact ledger gate.
- Scope/Trigger: Internal development/test deployments that change the migration ceiling or container provenance while stable and canary share PostgreSQL.
- Enforcement: The deployment preflight reads the same Compose labels from stable, canary, frontend and Nginx, freezes `--project-name unirouter`, the protected env-file path and all overlays in a secret-free manifest, applies the 80 percent/8 GiB storage gate, and follows the non-rolling CLI migration sequence in the runbook.
- Authority: `docs/ops/deployment-runbook.md` section 9.10.1; `scripts/docker-storage-preflight.sh`; `cmd/uniroute/main.go` exact runtime-schema gate; `internal/schemaauthority/version.go`.

### MAR-009 Separate stable failure identity from provider-controlled diagnostics

- Invariant: A provider-controlled response member may be retained only as bounded diagnostic evidence; it cannot create a dynamic error-code identity or become capability, usage, billing, routing or release authority.
- Scope/Trigger: Typed provider Probe or delivery validation needs to expose why a strict schema rejected an otherwise successful provider response.
- Enforcement: OpenAPI keeps `contract_error_code` closed and stores a syntax-constrained member identifier in a separate field without its value or the complete raw response body. The read projection splits historical 1.2.18 dynamic Kimi codes without rewriting immutable Probe summaries.

### MAR-010 Publish static capability contracts without rewriting dynamic evidence

- Invariant: A declaration-owned capability contract publication is an explicit, exact-artifact state transition; it must bind the approved Plan to the compiled declaration, complete migration bytes and expected ledger predecessor, while leaving Probe/Approval-owned lifecycle state outside the publisher's mutation authority.
- Scope/Trigger: Publishing or rolling back static capability bindings, current selectors or declared deployment projections after the M100 compatibility baseline.
- Enforcement: Ordinary startup and migration paths reject pending declaration-owned migrations and require a bijection between compiled declarations and exact generated artifact migrations. Publication up/down rejects incomplete validation, projection or verification hooks. The publication owner validates an exact ledger prefix, locks and recomputes the Plan, rehashes the bytes immediately before execution, binds projection predecessors to exact declared effects, verifies final static state in-transaction and performs a same-session readback. Guarded down refuses retained Freeze/provider-attempt execution evidence, and projection planning mutates only absent or `enabled/declared` rows. Generated artifacts are byte-stable with a single terminal newline. Historical rollback tests first establish the exact predecessor ledger instead of executing an older down artifact while a later declaration publication remains applied. Real PostgreSQL regressions cover non-prefix ledgers, declaration/migration inventory drift, incomplete writer hooks, artifact-byte drift, forged projection predecessors, lifecycle-owned projections, retained execution evidence and an actual M101 apply/down/reapply cycle.
