---

## 1. 设计目标

| 目标 | 时间 | 验收标准 |
|------|------|----------|
| 主目标 | 10 秒 | 新操作员能回答：流量多少？成功率多少？有异常吗？ |
| 次目标 | 30 秒 | 能识别异常来源（哪个模型/渠道出问题） |

---

## 4. Section 1: KPI Row

**高度**: 120px  
**布局**: 4 列 Grid

### Card 1: 总请求数
- 数据: `dashboard_overview.total_requests`
- 格式: 大数字 + Delta（vs 昨日）
- 颜色: 蓝 #0077FA

### Card 2: 成功率
- 数据: `dashboard_overview.success_rate * 100`%
- 格式: 百分比 + Delta（vs 昨日）
- 颜色: 绿 #05944F（正常）/ 红 #DD2C00（低于阈值）

### Card 3: 平均延迟
- 数据: `dashboard_overview.avg_latency_ms` ms
- 格式: 毫秒 + Delta（vs 昨日，负值=改善）
- 颜色: 橙 #F5A623（偏高）/ 绿 #05944F（正常）

### Card 4: 今日花费
- 数据: `dashboard_overview.today_cost_cents / 100` ¥
- 格式: 金额 + Delta（vs 昨日）
- 颜色: 紫 #7B61FF
- 附加: Budget Status 进度条（如有预算）

---

## 5. Section 2: AI 活动趋势

**高度**: 320px  
**宽度**: 100%

### 图表类型
- Area Chart（面积图）

### 数据源
- `daily_trend` API（需确认后端已返回）

### 指标
- 主指标: 请求数（默认显示）
- 可切换: 成本、延迟

### 时间范围
- 与 Header 的时间范围选择器联动

### 图例
- 右上角

---

## 6. Section 3: 模型活动分布

**宽度**: 70%

### 图表类型
- Horizontal Bar Chart（水平柱状图）

### 数据
- Top 5 模型按请求数排序
- 显示: 模型名 + 请求数 + 占比

---

## 7. Section 4: 渠道健康状态

**宽度**: 30%

### 布局
- Card Grid（卡片网格）

### 每个渠道卡片
- 渠道名称
- 状态 Tag（active/disabled/cooldown）
- 失败请求数

### 状态颜色
- active: 绿 #05944F
- disabled: 红 #DD2C00
- cooldown: 橙 #F5A623

---

## 8. Section 5: 最近请求

**高度**: 自适应

### 表格列
1. Request ID（monospace + 复制按钮）
2. 模型
3. 状态码（Tag 着色）
4. 延迟
5. Token
6. 费用
7. 时间

### 状态码着色
- 2xx: 绿
- 4xx: 橙
- 5xx: 红

### 交互
- 点击行跳转到 Logs 页面（带 request_id 筛选）

## 9. 数据依赖

| 数据 | API | 当前状态 |
|------|-----|----------|
| KPI 数据 | `GET /dashboard/overview` | ✅ 已实现 |
| 趋势数据 | `GET /dashboard/daily_trend` | ⚠️ API 存在但前端未渲染 |
| 渠道健康 | `GET /dashboard/channel_health` | ❌ 不存在 |
| 最近请求 | `GET /logs?limit=10` | ✅ 已实现 |

> **注意**: 趋势图需要先确认 `daily_trend` API 返回的数据格式，再决定是否需要调整前端渲染逻辑。
