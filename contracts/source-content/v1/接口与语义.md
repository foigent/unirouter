# C0 v1 接口与语义

本文件与 Schema 合用，属于 `1.0.0-candidate.2`。保留候选已经决定的接口路径；下列细化是普通工程候选，由原两主管审增量。所有示例值为合成，不是部署预设。

## 1. 版本、授权和配置

新 profile 固定 `unirouter.interaction-content.v1`。旧 `/source/v2/capabilities` 无任何字段增量，新 `/content-capabilities` 单独返回 `unirouter.content-capabilities.v1`。新入口 404 或未知 schema 只表示不支持 C 合同，不回退到旧 payload 字段。认证/授权/来源故障要单独保留。

发现、清单、正文都检查：当前连接 active、凭据 feed_active、连接与不可变注册的 C profile 交集、精确 source/org/project 范围，以及当前允许的用途。不能仅调用会接受 staged 的原 authenticateTx 就完成授权。采集配置生效不授予连接读取权；连接读取权也不授予 XI 任何用户正文权。

`ContentAccess` 是原来源控制模块中的局部授权投影，按既有 `registration_hash` 关联，**不是新凭据格式、可下载 Token 或额外 IAM**。新 C 凭据严格按 [R1 独立生命周期](R1-内容凭据生命周期.md) 的 content 作用域、显式管理路径及 credential_id/registration_hash 绑定处理，不能原样调用旧整项目轮换；旧 registration 的字节和哈希不改。用途/覆盖范围随 C 授权关联保存；撤回或范围变更推进 `content_scope_revision`，不推进未变 A/B/D 世代。恢复另推进 C `recovery_epoch`。只有 C 的注册与内容阅读都是合法配置。

`XIContentGrant` 对应既有 grant 的 `allow_content=false` 和用途集合。旧 grant 升级不扩权；不能用整组替换时漏填字段的方式误删其他能力。CLI/check、DB 准入、装载摘要、scope、会话/前端失效与复核入口须一起落地。`allowed_content_purposes` 不是浏览器自报许可。

内容配置 GET 返回 desired/effective 两个版本及 effective_at。PUT 的 expected_policy_version 比较当前 desired 版本，原子 CAS；成功受理取得下一版本。已生效返回 200 且两者相同；延后应用返回 202、pending 和仍真实生效的旧版本。失败不得伪装 applied。400 表示配置不支持/超限，409 仅表示实际版本冲突。真实项目管理资格由原管理身份及项目归属校验，Feed 凭据不得使用该入口。

full_content/redacted 必须给有限 retention_seconds、quota_bytes、max_saved_bytes、allowed_purposes。disabled/metadata_only 不伪装已有正文存储设置；关闭只影响新采集，不自动撤销或删除历史。redacted 还须准确 redaction_ref，能力未声明则不能启用。Schema 接受某模式的表达不证明某个版本已支持该模式。

limits 来自该部署真实配置与实现。`max_read_bytes` 至少覆盖允许保存和仍承诺可读的保留表示；`max_buffer_bytes` 是每次读的内存上限，整个并发预算仍由既有资源控制管理。大表示可在原部署受控临时存储内验证，不引入服务或永久副本。单项 max_saved 不得大于项目配额或部署支持限额。示例的 7 天、1 GiB、32 MiB 均不作为客户默认值，也不放宽原性能要求。

## 2. 首拉、进度与身份

`Boundary` 的 `after_sequence` 是排他下界，`time` 是该边界建立时的 UTC 注释，不能由客户端时间代替源端授权。源端在授权登记时将批准的历史覆盖映射并固定成 C 序列下界；不得把恢复时间或当前 high 当成批准起点。权限范围始终还要校验完整来源/项目。

无 cursor 首拉从 `max(coverage_from.after_sequence, retention_floor.after_sequence)` 开始，返回其后的仍保留清单，**首响应即包含符合条件的已有数据**。retention_floor 越过获准起点时必须返回 retention_floor_ahead 缺口。`bounded` 仅表示本页声明的序列范围内未报告已知缺口，不代表所有模型内容完整。

后续按独立 C 游标读。沿现有 HMAC、长度前缀/范围绑定与分页实现增加 C 协议域 `unirouter.source-content-cursor.v1`，绑定 source_instance、org_id、project_id、C profile、content_scope_revision、recovery_epoch、sequence。线上的版本字节由 UR 在现有实现中分配；示例没有生成真签名或声称旧游标可用。不能解码 A/B/D 游标为 C；C 范围或 epoch 变更返回明确冲突，落在已清理前缀返回 cursor_expired。恢复/撤回不能伪装正常空页。

`sequence` 是 C 采集/修订入库顺序，`occurred_at` 是原观察时间；迟到修订即使发生时间早，也取得新 sequence。页内序列递增，`last_sequence` 是最后返回位置，空页保持 after_sequence；high_watermark_sequence 是该页查询快照上界。next_cursor 总是返回，以便继续轮询；has_more 仅表达该快照是否还有后续 C 序列。端点必须按 C 范围维护进度，不依赖 A/B 是否追平。

Manifest 继续使用原字符串 org/project/revision、UTC 六位微秒、`uf1_` 标识和 `sha256:` 摘要。身份算法复用当前 UR sourceID：每个 UTF-8 分量前加四字节大端字节长度，再 SHA-256；只新增独立域与必要分量：

```text
source_fact_id = sourceID(
  "unirouter.content-manifest.v1", source_instance, org_id, project_id,
  "unirouter.interaction-content.v1", request_id,
  observation_point, attempt_id 或空字符串, content_item_id)
event_id = sourceID("unirouter.content-manifest.v1.revision", source_fact_id, revision)
```

content_item_id 在捕获开始时确定，例如一个观察点的 body-0；content_ref 和最终 digest 不参与逻辑身份。provider_request/provider_response 必须有真实 attempt，改写前 client_request 和实际外发 provider_request 分开。不同 attempt、观察点和来源不能因为正文相同合并成同一事实。缓存未调用提供方时不编造 provider 事件。

revision 1 禁止前驱字段；后续 revision 必须等于前驱 + 1，previous_hash 对应原前驱完整 canonical Manifest 的 sha256，correction_reason 非空。canonical 复用现有 CanonicalJSON（固定字段名，UTF-8、无额外空白、对象键排序、整数）；生产解码继续使用原严格 JSON 扫描，拒绝重复键、非法 Unicode、null、未知字段和非 canonical 输入。Schema 校验不是原始 JSON 扫描器。

`source_sha256` 散列 Manifest，**不含外层 sequence 或当前 availability**。pending 与 not_captured 无可读引用；complete/partial 必须有耐久保存表示、captured_at、expires_at。pending→complete/partial 是同一事实修订。完整捕获错误回复可以 complete；截断工具参数只能 partial，不能据此断言工具成功。

正文先有界临时写、耐久化，再发布可读引用。文件成功而清单提交失败时不对外编造成功清单；由来源健康和有界恢复暴露/修复，健康也无法可靠落地时显示范围 unknown。缺口表允许范围未知，不虚构丢失条数。正文到期、删除、缺失或损坏仅改变当前 availability，不能倒改历史捕获完整性。

## 3. 保存表示与 HTTP 字节

`uc1_` + 64 位小写十六进制是不透明 content_ref 的工程候选。真实值由存储模块生成并查受控映射；不得将用户字符串拼成路径或从引用解出 URL。改变脱敏、重编码或任何可见字节需新引用；同一引用永久绑定相同表示。它不是源文件版本，也不是正文下载权限。

`saved_bytes` 与 representation.digest 对准**选定保存表示在 HTTP Content-Encoding 之前的字节**，不是原文件权威版本、tokens、解码字符数或物理压缩文件占用。v1 wire encoding 固定 identity；存储内部压缩可透明还原同一表示，不增加第二种传输编解码。application/gzip 样例只是二进制内容，按原字节散列，不自动解压或执行。

UR 正文路径用 content_ref；查询仅 request_id、source_fact_id、revision、purpose。XI 路径用既有 reading_id/request_ref/content_ref；查询仅 source_fact_id、revision，浏览器不提交 purpose，服务端人工查看入口固定 human_review 并校验当前主体。各字符串只做标准 URL 编码，未知查询拒绝；源地址来自 XI 受管连接配置。

正文成功为 HTTP 200 原始字节，0 字节也返回 200，不能用 204 混为缺失。候选 HTTP 元数据如下：

| 头 | 值/检查 |
| --- | --- |
| Content-Type | application/octet-stream；实际保存 media_type 在 ReadMetadata |
| Content-Length | representation.saved_bytes 的十进制值，含 0 |
| Content-Encoding | 不设置，或 identity；不额外压缩已承诺的表示 |
| X-UR-Content-Metadata | ReadMetadata canonical UTF-8 的无填充 base64url；客户端解码后按 Schema 与冻结引用核验 |
| Cache-Control | UR no-store；XI private, no-store |
| X-Content-Type-Options | nosniff |
| Content-Disposition | attachment; filename="content.bin" |
| XI 现有 scope 头 | 保留 X-XInsight-Scope-Revision 与现有授权表示标识 |

这是元数据小头，不是把正文变成 JSON/base64；不新增任意下载目的地。协议 v1 不引入 Range/续传/分片 API；收到 Range 返回 400 unsupported_range。后续如确需续传须单独明确复核边界，不能默认为已支持。

最低充分读取顺序：

1. XI/UR 各自做短的当前授权、成员与来源范围检查，记录会话/权限/C 世代；释放授权事务锁后再等待正文 I/O。
2. 以声明上限有界取得所选表示；XI 可使用本次读取的受控临时文件，不能把整个大表示塞入原 16 MiB JSON 缓冲。核身份、长度和 digest 后才发布为完整内容；中断或错误表示不展示成成功。
3. XI 发布首字节前再次查当前会话、grant、C 世代、成员、到期及源端授权。保存字节大于 16 MiB 但仍在承诺范围内不能被静默截断；临时 I/O/容量故障显示不可用并清理本次临时文件。
4. UR/XI 每次下一有界写块前重新判当前授权/到期；写阻塞设取消边界，撤权或会话变化取消余下交付。已进入系统/网络缓冲的当前块无法保证追回；真实实测需报告单块/缓冲上限和撤权至停止时间，不能承诺瞬时收回已送达字节。不能让整段慢响应长期占授权事务。
5. 浏览器只在完整读取、长度/摘要成功且 scopeSessionKey 仍匹配时呈现；换页/撤权/换会话取消请求、清当前显示，迟到结果丢弃。任何 HTML、Markdown 链接、脚本或工具参数仅当惰性数据处理，不执行、不自动展开远端资源。

这组步骤是**产品必须实现并测试的合同**。离线脚本只生成字节并校验摘要，未实现真实暂存、HTTP/流式、撤权或取消。

## 4. XI 内容阅读、定位与复核

复用现有 runtime reading 创建/请求关联入口，不增加 B 权限要求。合格 C 清单或准确 I01 执行关联可产生内容成员；原 B 观察成员与所有 B 统计仍按原分母查询，不能因为共享 request 表而把仅内容请求计入 B。费用/执行打开内容时沿原期间、筛选和返回状态；不另取最近 24 小时替代原阅读范围。

新增成员冻结 source_system_id、完整 UR 范围、source_fact_id/revision/source_sha256 及表示引用。XI 的 source_system_id 绑定受管来源，不从 UR 正文读入。新内容 interpretation 固定 `xinsight.content-membership.v1`；空内容扩展对旧 reading 摘要贡献零字节，非空扩展须明确版本、排序与散列，由 X1 按原 membership 实现定向落地。

`newer_revision_available` 只提示可刷新，不替换旧成员；新 reading 才纳入迟到完成/纠正。availability 在请求时单独求值，不写回历史 Manifest。无权者在成员/引用返回前被拒绝，不能返回“已保存但无权”的敏感引用列表。已授权用户才能区分到期/故障。

ContentProjection 仅保存解析位置与最小消息/工具关系，不复制参数或结果。byte_range 以保存表示的字节定位，offset+length 不超过 saved_bytes；JSON Pointer 依保存表示实际可解析的 JSON 定位。exact_protocol_id 按 kind 校验：message 要求 protocol_message_id + session_ref，tool_call/tool_result 要求 tool_call_id + session_ref，不要求消息虚构工具ID。工具关联还须完整来源/项目/请求/会话及协议依据；同名 ID 不跨范围连接。partial 不可解析时保留原字节与缺口，不能补造成功工具动作。

复核 ContentChoice 采用稳定 FrozenManifestRef、位置和 supports/contradicts/context，不采用临时 reading URL，不复制正文。采用、支持/反驳、结束核验、队列、封存/续办、pack/恢复都要覆盖。历史恢复验证原引用/动作链，不要求历史操作者今天仍有 grant；恢复成功也不允许当前无权者取正文。到期后保留原判断并显示当前不可取。确需摘录时按原约定受限派生内容另行实现权限/保留，本 v1 引用结构不提供可永久保留摘录的捷径。

## 5. 错误与恢复动作

源端内容接口复用实际 URError 壳；XI 复用 XIProblem。安全错误不含路径、正文、引用摘要或密钥。

### R2：三个 C 读取入口的拒绝顺序

`content-capabilities`、`content-manifests`、`contents/{content_ref}` 统一采用下列顺序。前提是已完成原认证、精确来源/组织/项目和 IP 等检查；认证失败不进入本状态表。此处只承接已认证状态，不将 staged 当作激活，也不在拒绝前查出或泄露正文引用、摘要、内容可用性。

| 按顺序命中的状态 | HTTP / code / retryable | 恢复动作 |
| --- | --- | --- |
| C profile 不同时存在于连接与该不可变注册的当前允许交集 | 403 / profile_not_authorized / false | 停止自动重试，由有权管理者核对并显式修正该 C 范围；不得回退到 A/B/D 或旧 payload |
| 上项通过，来源的有效 C 读取状态为 paused（包括整连接暂停） | 503 / source_paused / true | 按既有退避等待明确恢复；原 helper 返回 Retry-After: 1；暂停期间三接口均不能成功返回 C 数据 |
| 前两项通过，凭据仍为 feed_staged | 409 / staged_credential_requires_pause / false | 停止拉取，由管理员按 R1 完成正确 C 激活或取消；XI 不得自动暂停全连接，也不能让 paused 的 staged 读 C |
| 三项均通过 | 继续当前范围/用途、成员、生命周期及完整性校验 | 不代表已经获准正文，更不跳过最终权限复核 |

缺 profile、paused、staged 同时存在时按最先命中项返回；有 profile 的 paused+staged 返回 source_paused，而不是 200 或 staged 的409。`staged_credential_requires_pause` 是沿用的既有码名，不能解释为“暂停后 staged 可读取内容”。R1 的全连接和 C 局部状态共同决定有效 C 读取状态，全连接安全停止仍阻止 C。

来源依据：[handler.go:201](/Users/m4/Desktop/test/ur-regression-20260914/source/internal/sourcefacts/handler.go:201)至210的实际顺序；[budget_handler.go:140](/Users/m4/Desktop/test/ur-regression-20260914/source/internal/sourcefacts/budget_handler.go:140)和[runtime_current.go:251](/Users/m4/Desktop/test/ur-regression-20260914/source/internal/sourcefacts/runtime_current.go:251)相同。[writeError:65](/Users/m4/Desktop/test/ur-regression-20260914/source/internal/sourcefacts/handler.go:65)保留 wire 壳、no-store 和重试头。旧[capabilities:167](/Users/m4/Desktop/test/ur-regression-20260914/source/internal/sourcefacts/handler.go:167)有 paused/staged 预检成功特例；旧入口保持，新 C 发现入口不继承该例外。

R2 Schema 同时约束 code/retryable；HTTP 描述片段约束 HTTP/code/retryable 三元组，http_status 只属于离线响应描述，线上不加入 error body。向量分别拒绝错误状态码、错误 retryable 和把合法错误三元组映射到错误状态的情况；每个状态向量明确覆盖这三个入口。它们验证声明的合同，不运行认证器或 HTTP，不证明产品权限已执行。

XI 来源适配器应保留上游三个 code 的区别，分别标成缺 C 授权、来源暂停、凭据未激活；不得将 source_paused 归类为不支持 C。终端用户既有会话/范围错误合同不变，上游连接状态由原来源状态/诊断路径呈现，不能藉诊断增加正文可见性。

| 条件 | UR 来源接口 | XI 当前工作台 |
| --- | --- | --- |
| 无认证 | 401 unauthorized，非自动重试 | 401 authentication_required |
| 无 C profile 交集 | 403 profile_not_authorized，retryable=false；三个C入口一致 | 来源状态保留缺C授权原因；用户端仍经现有范围拒绝，不提供引用 |
| C 来源已暂停 | 503 source_paused，retryable=true；三个C入口一致 | 来源状态显示暂停并退避，不标记不支持 |
| C 凭据仍 staged（交集及active检查已通过） | 409 staged_credential_requires_pause，retryable=false | 来源状态要求正确激活；不靠重试或暂停整连接取得读取 |
| 当前内容不属于已授权范围/请求 | 按原防枚举先授权；404 not_found，不泄露当前可用性 | 403 permission_denied/workbench_scope_denied；非成员404 workbench_record_not_found |
| 签名/输入非法 | 400 invalid_cursor/invalid_request | 400 invalid_workbench_request |
| 内容世代/恢复 epoch 变更 | 409 content_scope_changed/source_epoch_changed；显式重新预检/重同步 | 409 scope_revision_changed/workbench_access_changed，丢弃旧响应并刷新 |
| 已授权可知且到期 | 410 content_expired；不自动重试 | 410 content_expired；旧 reading 自身到期仍为 workbench_reading_expired |
| 清单游标过保留边界 | 410 cursor_expired；显式恢复范围/缺口 | 来源状态要求处理，不改成正常空数据 |
| 尚未就绪/来源暂故障 | 503 content_pending/source_unavailable，retryable=true | 503 content_pending/content_source_unavailable，retryable=true |
| 正文缺失/损坏/表示不符 | 503 content_missing/content_corrupt/representation_mismatch，retryable=false | 503 content_missing/content_integrity_failed，retryable=false |
| 旧 runtime 未支持 C | 新发现入口404；明确不支持时 content_not_supported | 显示不支持 C；不读旧 payload 绕过 |

UR 原 source helper 的 safe_message/recovery 字段保持通用值，具体可恢复动作由 code 映射；retryable=true 的 Retry-After 沿原 helper。项目策略 API 不复用 source helper，保留原管理封装与精确 HTTP 状态。新 code 与错误映射属于本次增量审查，不修改旧 code 的含义。响应已开始后遇到撤权/中断，必须终止交付；不能把 JSON 错误拼进正文尾部。
