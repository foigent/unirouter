## 2. 管理选择与绑定合同

沿同一管理模块增加显式C路径：

- `GET /api/v1/data-exchange/xinsight/source-connections/{project_id}/content`
- `POST /api/v1/data-exchange/xinsight/source-connections/{project_id}/content/{action}`，action限定prepare、rotate、activate、cancel、pause、resume、revoke。

路径就是content作用域选择，不能靠猜测credential_id、改写旧registration或默认把旧接口解释成C。旧客户端不调用新路径，旧GET/DTO保持原字段和legacy凭据语义，不把新增C凭据混入其“唯一active/staged”结果。C的新查看输出需明确全连接安全状态和C局部状态，不能以C局部active掩盖全连接暂停。

请求及绑定沿下列最小规则；U1负责在既有严格解码器旁实现C的具名DTO，并将准确wire实例交XI增量核对，不重新展开产品讨论：

| 动作 | 必须选择/绑定 | 结果与禁止项 |
| --- | --- | --- |
| prepare | 原Registration完整格式，profiles精确为C；原格式的allowed_ip；由既有Registration.Hash按原序列化字节计算registration_hash | 只创建C staged；原A/B/D可持续工作，不要求全连接暂停。operation_id保持现有不可混用/幂等规则；不同哈希不得重用同一操作身份。 |
| rotate | 原C active的credential_id与registration_hash；新的C-only Registration | 只准备新的C staged，旧C active在明确切换前保持原受限能力。网络绑定继承原C，不从A/B/D借用；不撤旧A/B/D。 |
| activate | 准确C staged credential_id＋registration_hash | 事务核对局部状态及原控制资格后，只撤换C active并激活该staged；只推进C失效域。不能批量撤同purpose全部key。 |
| cancel | 准确C staged credential_id＋registration_hash | 仅取消该staged；现有active及其注册/游标不变。不能把取消待激活凭据当作撤回已用C权限。 |
| pause/resume/revoke | 当前C active的credential_id＋registration_hash；不存在active时由明确局部状态/版本处理，不能隐式选择legacy | 只影响C；revoke撤销C active及staged并覆盖在途读/旧凭据/游标，旧staged不能随后被激活。resume不能恢复已撤销凭据或越过全连接安全停止。 |

prepare/rotate响应必须包含新C credential_id和服务端计算的registration_hash，以供激活/取消准确绑定。相同操作、凭据和哈希的合法重放不创建第二份凭据；目标过时、跨作用域、哈希不符或并发状态已变，应冲突拒绝而不是选择“最新一把”。具体原管理错误壳保持，不能混用C读取URError。

注册哈希准确沿用`Registration.Hash()`中的`json.Marshal(r)`再`HashSourceBytes`，不是把请求任意重新做键排序CanonicalJSON。执行事实/投影的canonical算法与注册身份算法各守其既有合同，不混用。

`ContentAccess.registration_hash`必须绑定这里的准确C注册，并与已接受的profile、用途、获准覆盖起点及C范围版本一起核验。它是原受管来源配置的局部授权投影；不是第二份Token，也不是凭一个哈希就取得权限。凭据staged、仅一侧有C、用途不允许或全连接暂停时，三个C读取入口均不得成功。

XI在同一受管source_system_id/source_instance/org/project下保存legacy和C的具名绑定，分别选择凭据与进度。不能把同一源的C另造一个无关联来源身份，或以C缺失替换原A/B/D凭据。只有C、以及I01+C无B的配置必须可成立；管理员无需先授权A/B/D来搭建C。该内部绑定由既有安装/配置入口完成，不要求客户手工理解数据库作用域。

## 3. 全连接安全动作与局部状态

| 动作 | legacy A/B/D | C | 边界 |
| --- | --- | --- | --- |
| 新C prepare/activate/rotate/pause/resume/revoke | 原有效token、注册hash、游标和进度不变 | 仅按本作用域推进 | 启C不能暂停正在工作的旧资料供数。 |
| 原legacy prepare/rotate/activate/cancel/profiles | 沿原合同处理legacy范围 | 不因purpose相同而被批量撤销/替换 | 原D局部变更等已承诺隔离继续。 |
| 原全连接pause/revoke | 停止对应读取 | 同时停止对应读取 | 保留原全连接安全控制，不被C新路径规避；只有C的项目也必须可操作此安全停止。 |
| 原全连接resume | 沿已授权/已配置状态解除全局pause | 仅解除全局阻挡；不重建C授权或取消C局部pause/revoke | 先核所有适用的原资格与状态，不允许局部resume绕过全局pause。已revoked凭据只能通过正式重新登记流程恢复。 |

内容采集策略、模型准入和C证据读取分别保持原权威：局部撤C读取不自动修改模型/金融终态，也不等同删除已保留正文。停止新采集与历史读取/保留按原55和candidate.1合同执行。

## 4. 实现接点与验收

U1可以选择最小列/表/索引，不在本合同猜迁移编号或强制特定存储布局。必须一并处理：M116唯一索引和purpose约束、按project/purpose的计数/锁/查询/批量撤key、旧GET结果、C-only配置、全连接安全状态、原来源认证及恢复。只迁移旧行的内部作用域归属，不重新序列化旧registration、不重算其hash。原有已支持版本的迁移/回退应明确支持或拒绝，不能让旧runtime把两组凭据当成一个有效组继续写入。

旧许可、数量和创建权限照常约束新增测试/客户凭据，不能因增加C自动抬高额度。新配置接口与key创建是产品实现能力，本次本地编码放行不是执行任何真实环境的凭据操作授权。

关闭R1沿原P02/P03/P14，必须在产品中验证以下内容，本文件没有运行这些测试：

1. 同项目旧A/B/D在用→C登记/激活→只轮换/撤C：旧token、cursor、registration_hash持续有效，旧C按约定失效。
2. 仅C项目可完成登记/读取/暂停/撤回；无需先造A/B/D。相同来源身份仍可进入XI无B工作链。
3. 指定错误credential、哈希、旧staged、legacy key或混合profiles均拒绝；不会误选“最新”凭据。
4. 同时prepare/rotate/activate/cancel和全连接pause/revoke竞争，局部唯一性、最终状态和停止效果有真实PG证据；只取消staged不撤active。
5. 全连接停止阻挡两组，C局部resume不能越过；解除全局pause不恢复已撤C权限。
6. 旧消费者GET、原管理调用和旧注册字节兼容；新状态恢复后保留准确作用域、凭据绑定及独立世代。旧runtime不支持时拒绝相关写入并保留数据。

总体选择以上作用域/端点/绑定及安全语义；具体DTO的细节、事务与迁移由UR主管增量审查、XI核接入形状后实施，无需再让用户选择表/字段或重复批准本地代码。
